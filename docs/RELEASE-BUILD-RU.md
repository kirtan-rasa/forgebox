# Сборка и публикация релизов ForgeBox

## Что собирает и публикует workflow

Основной workflow находится в `.github/workflows/release.yml`. Он собирает четыре установочных пакета:

- Fedora RPM;
- Debian/Ubuntu DEB;
- AppImage;
- нативный пакет Arch Linux.

В публичный релиз также входит ASCII-armored публичный ключ проверки подписи RPM: `forgebox-rpm-signing-key.asc`. Приватный ключ остаётся исключительно в GitHub Secrets.

Workflow запускает `cargo test` и `cargo check`, проверяет пакеты и подпись RPM. Для каждого опубликованного файла GitHub предоставляет SHA-256 digest через API; установщик использует его для проверки загруженного пакета.

Промежуточные файлы сборки, отладочный пакет Arch, `PKGBUILD`, `.SRCINFO` и временный архив исходников остаются во внутренних CI artifacts и не прикрепляются к публичному релизу.

## Как работает CI

- Pull request: тесты, проверка исходников и сборка Linux-пакетов.
- Push в `main`: те же проверки и сборки без публикации релиза.
- Push тега `v*`: проверки, сборки и публикация GitHub Release.
- Ручной запуск: доступен через **Actions → ForgeBox Linux builds → Run workflow**.

Для воспроизводимости workflow сначала подготавливает один `Cargo.lock`, затем использует его в остальных job.

## Подготовка релиза

1. Обновите `version` в корневом `Cargo.toml`.
2. Обновите версию пакета ForgeBox в `Cargo.lock` (или выполните `cargo check`, чтобы Cargo обновил его).
3. Обновите `CHANGELOG.md`.
4. Отправьте изменения в pull request или в `main`.
5. Дождитесь успешного завершения всех проверок и сборок.
6. Создайте тег, совпадающий с версией в `Cargo.toml`.

Например, для версии `0.4.1`:

```bash
git tag v0.4.1
git push origin v0.4.1
```

Тег и `Cargo.toml` обязаны совпадать. Workflow проверяет это перед публикацией.

Не используйте уже опубликованный тег повторно: для следующей сборки увеличьте версию и создайте новый тег.

## Подпись RPM

Для публикации подписанного RPM в настройках репозитория должен существовать GitHub Actions secret:

- Имя: `RPM_SIGNING_PRIVATE_KEY`
- Значение: ASCII-armored приватный ключ, выделенный только для подписи RPM ForgeBox.

Приватный ключ хранится только в GitHub Secrets и не должен попадать в репозиторий, issue, pull request или GitHub Release. Публичный ключ публикуется в релизе отдельным файлом `forgebox-rpm-signing-key.asc`; файл `forgebox-rpm-signing-key-id.txt` больше не публикуется.

Инструкция по созданию ключа, его экспорту, импорту публичной части и проверке пакета находится в [Linux packages](LINUX-PACKAGES.md).

## Проверка результата

После публикации откройте вкладку **Releases** и проверьте наличие ровно пяти прикреплённых файлов:

- RPM;
- DEB;
- AppImage;
- Arch `.pkg.tar.zst`;
- публичный ключ `forgebox-rpm-signing-key.asc`.

Отладочный пакет, метаданные Arch и временные файлы не должны попадать в публичный релиз.
