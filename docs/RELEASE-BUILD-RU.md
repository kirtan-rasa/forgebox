# Сборка установщиков ForgeBox для Fedora и Windows

Этот набор добавляет упаковку и автоматическую сборку к **уже существующему исходному проекту ForgeBox**. Он не заменяет `src/main.rs`, `src/engine.rs` или пользовательские изменения интерфейса. GitHub Actions собирает настоящие бинарники на целевых системах: Fedora RPM в Fedora-контейнере и Windows-инсталлятор на Windows runner.

## 1. Применить набор к проекту

Распакуйте архив `forgebox-release-kit.zip` **в корень Вашего рабочего репозитория**, где лежит `Cargo.toml`, объединив каталоги. Не распаковывайте поверх проекта старый ZIP исходников: так можно потерять свежие исправления адаптивности.

В терминале из корня репозитория выполните:

```bash
python3 scripts/apply-release-kit.py
bash scripts/enable-native-wayland-dnd.sh
cargo test
cargo check
```

Скрипт патча сначала проверяет все ожидаемые фрагменты, затем создаёт резервные копии изменяемых файлов с суффиксом `.release-kit.bak`. Если структура исходника отличается, он должен остановиться, не записывая частичные изменения. Проверьте `git diff`, особенно изменения в `Cargo.toml`, `src/engine.rs` и `src/main.rs`. Я намеренно не делаю `cargo fmt -- --check` блокирующим шагом CI: форматирование исходника исторически не было единообразным, и не стоит запрещать выпуск бинарника из-за косметического diff всего интерфейса.

В этой среде не установлены `cargo`, `rustc`, `rpmbuild` или Windows/Inno Setup, поэтому полученные установщики нельзя честно представить как уже собранные и протестированные. Для этого настроен CI.

## 2. Сначала проверить CI без публикации релиза

1. Закоммитьте проверенные изменения и отправьте ветку на GitHub.
2. Откройте репозиторий GitHub → **Actions** → **ForgeBox release builds** → **Run workflow**.
3. Дождитесь окончания всех заданий. Если одно упадёт, откройте его лог и исправьте ошибку до создания тега.
4. В успешном запуске скачайте артефакты: `forgebox-fedora-x86_64` и `forgebox-windows-x64`.

Workflow подготавливает один `Cargo.lock`, запускает тесты, готовит закреплённую версию патча `winit`, затем собирает приложение. RPM создаётся на Fedora; EXE и Inno Setup installer создаются на Windows.

## 3. Опубликовать релиз с файлами для скачивания

Версия в корневом `Cargo.toml` сейчас `0.2.0-beta.1`. Тег должен совпадать с ней, включая beta-часть. Сначала убедитесь, что такой тег ещё не существует и что CI прошёл успешно, затем выполните:

```bash
git tag v0.2.0-beta.1
git push origin v0.2.0-beta.1
```

Если Вы меняли `version` в `Cargo.toml`, используйте соответствующий новый тег вместо приведённого примера. Публикация по тегу автоматически создаст GitHub Release с RPM, Windows installer и portable ZIP. Не публикуйте тег до проверки ручного workflow: иначе CI превратит простую ошибку сборки в публичный релиз с отсутствующими файлами.

## Fedora

Загрузите RPM из GitHub Release, затем установите его командой:

```bash
sudo dnf install ./forgebox-*.rpm
```

RPM регистрирует приложение в меню с иконкой и объявляет основные системные конвертеры как RPM-зависимости. DNF установит доступные обязательные зависимости автоматически. FFmpeg помечен как рекомендуемый пакет, так как на некоторых системах для него нужен RPM Fusion. Удаление выполняется через менеджер пакетов, например `sudo dnf remove forgebox`.

## Windows

`ForgeBox-Setup-x64.exe` устанавливает приложение для текущего пользователя, добавляет пункт в меню «Пуск» с иконкой и при выборе может создать ярлык на рабочем столе. `ForgeBox-portable-x64.zip` содержит переносимую папку с EXE, иконкой, лицензией и заметками. Иконка встраивается также непосредственно в исполняемый файл.

Часть конвертеров поставляется отдельно от ForgeBox. В установленном меню «Пуск» добавлен ярлык **Windows conversion dependencies**, который запускает скрипт WinGet для установки ImageMagick, Poppler, Ghostscript, qpdf, Tesseract и ExifTool; LibreOffice и FFmpeg включены как опциональные для скрипта пакеты. После установки зависимостей закройте и откройте ForgeBox заново, чтобы получить обновлённый `PATH`.

Есть ограничения: для PDF watermark нужен `pdftk.exe` в `PATH`, а удаление фона требует отдельной настройки `rembg` и Python-моделей. В установщик не включены все сторонние конвертеры: их объединение увеличило бы размер и усложнило обновления/лицензирование. Поэтому Windows-инсталлятор устанавливает приложение, но не является автономным пакетом со всеми движками.

У Windows-EXE и установщика нет цифровой подписи издателя. Windows SmartScreen может показать предупреждение для скачанного файла. Это не исправляется настройкой Inno Setup: для подписи нужен действительный сертификат code-signing.

## Изменения в исходниках

Набор переносит генерацию QR-кода внутрь приложения через Rust-зависимость, чтобы не требовать `qrencode`, добавляет Windows-совместимый поиск типичных команд внешних конвертеров, открытие выходной папки через Explorer и внедряет иконку в Windows EXE. На Linux остаётся прежняя логика использования системных команд.
