# Сборка и публикация релизов ForgeBox

## Что собирает текущий workflow

Основной workflow находится в `.github/workflows/release.yml`. Сейчас он собирает Linux-версии:

- Fedora RPM;
- Debian/Ubuntu DEB;
- AppImage;
- нативный пакет Arch Linux.

Workflow также запускает `cargo test` и `cargo check`, проверяет пакеты и публикует SHA-256 суммы. GitHub автоматически добавляет к релизу ссылки на архивы исходного кода.

## Как работает CI

- Pull request: тесты, проверка исходников и сборка Linux-пакетов.
- Push в `main`: те же проверки и сборки без публикации релиза.
- Push тега `v*`: проверки, сборки и публикация GitHub Release.
- Ручной запуск: доступен через **Actions → ForgeBox Linux builds → Run workflow**.

Для воспроизводимости workflow сначала подготавливает один `Cargo.lock`, затем использует его в остальных job.

## Подготовка релиза

1. Обновите `version` в корневом `Cargo.toml`.
2. Обновите `CHANGELOG.md`.
3. Отправьте изменения в pull request или в `main`.
4. Дождитесь успешного завершения проверок и сборок.
5. Создайте тег, совпадающий с версией в `Cargo.toml`.

Например, если в Cargo указана версия `0.2.0-beta.3`:

```bash
git tag v0.2.0-beta.3
git push origin v0.2.0-beta.3
```

Тег и `Cargo.toml` обязаны совпадать. Workflow проверяет это перед публикацией.

Не используйте уже опубликованный тег повторно: для следующей сборки увеличьте версию и создайте новый тег.

## Подпись RPM

Для публикации подписанного RPM в настройках репозитория должен существовать GitHub Actions secret:

- Имя: `RPM_SIGNING_PRIVATE_KEY`
- Значение: ASCII-armored приватный ключ, выделенный только для подписи RPM ForgeBox.

Приватный ключ хранится только в GitHub Secrets и не должен попадать в репозиторий, issue, pull request или GitHub Release. Публичный ключ и его fingerprint workflow публикует отдельно, чтобы пользователи могли проверить подпись RPM.

Инструкция по созданию ключа, его экспорту, импорту публичной части и проверке пакета находится в [Linux packages](LINUX-PACKAGES.md).

## Проверка результата

После публикации откройте вкладку **Releases** и проверьте наличие:

- RPM, DEB, AppImage и Arch `.pkg.tar.zst`;
- файла `SHA256SUMS`;
- публичного ключа и идентификатора ключа для проверки подписи RPM.

Отладочные пакеты и временные файлы не должны попадать в публичный релиз.
